# MVP 产品需求文档

## 1. 文档目标

定义 `Agent 指挥台` MVP 阶段必须交付的用户价值、功能范围、信息架构、验收标准与优先级，为产品、设计、研发和测试提供统一依据。

## 2. 产品定位

面向中国 OPC 的 Agent 团队管理与可信交付平台。

一句话定义：

> 像管理团队一样管理 Agent，像交付项目一样交付 AI 产能。

## 3. 目标用户画像

## 3.1 核心画像 A：接单型独立开发者

- 同时维护多个客户项目
- 使用多个国内外 AI 工具
- 需要给客户看进度、交付结果和证明材料
- 缺少标准化流程和透明协作界面

## 3.2 核心画像 B：超轻工作室负责人

- 2-10 人混合真人与 Agent 协作
- 项目多、时间紧、交付节奏快
- 希望沉淀固定工作流模板
- 希望减少沟通和追进度的管理成本

## 3.3 核心画像 C：AI Native 产品团队

- 将 AI 作为日常生产能力使用
- 需要统一接入各种 Agent、脚本和工具
- 重视效率、可审计和系统扩展性

## 4. 用户核心任务

- 我想在一个项目里看到所有 Agent 的角色、状态和任务进展
- 我想把重复交付流程做成模板，避免每次从头安排
- 我想在手机上审批关键节点、处理异常和查看状态
- 我想把项目过程整理成客户可接受的证明书
- 我想知道每次运行到底产生了什么结果、谁批准了、哪里失败了

## 5. 设计原则

- 项目优先：所有操作以项目和任务为中心组织
- 控制优先：小程序负责调度、审批、追踪，不承担复杂配置
- 过程优先：所有关键运行都必须留痕并可回溯
- 模板优先：高频重复流程尽量模板化
- 人机协作优先：任务负责人可以是 Agent，也可以是真人

## 6. MVP 功能范围

## 6.1 P0 模块

### A. 工作区与项目管理

- 创建工作区与项目
- 维护项目状态、负责人、客户信息、目标日期
- 项目下查看任务、运行记录、产物和证明书

验收标准：

- 用户可以创建项目并进入项目工作台
- 每个项目至少可以看到任务列表、运行列表和交付证明入口

### B. 任务与看板

- 看板视图、列表视图
- 任务状态流转：`Backlog / Planned / In Progress / Waiting Approval / Blocked / Completed / Delivered`
- 任务负责人支持真人或 Agent
- 任务支持优先级、截止时间、依赖关系
- 支持评论、催办、重试、回滚标记

验收标准：

- 任务状态流转可配置默认流程
- 任务详情页可追溯关联的 Run、Artifact 和 Approval

### C. Agent Registry

- 注册 Agent 基本信息：名称、头像、角色、标签、描述
- 记录 Agent 接入方式、能力列表、可执行任务类型、可用状态
- 可将 Agent 绑定到项目和工作流节点

验收标准：

- 用户可以在 Agent 列表中查看状态、角色和最近活动
- 每个 Agent 至少支持一种接入方式

### D. 工作流模板与执行

- 创建工作流模板
- 节点类型：任务节点、审批节点、条件节点、通知节点
- 触发方式：手动、Webhook、定时
- 固定节点绑定固定 Agent
- 失败后支持重试和人工接管

验收标准：

- 至少支持 3 个内置模板场景
- 模板实例化后能够生成对应 Task 和 Run

### E. Run 追踪与审批

- 查看 Run 状态：排队中、运行中、成功、失败、等待审批、已取消
- 记录 Run 输入、输出摘要、耗时、错误原因、关联 Artifact
- 支持审批、驳回、重试、催办

验收标准：

- 用户能从任务详情跳转到相关 Run
- 审批动作能够被记录并写入时间线

### F. 小程序轻指挥端

- 查看项目列表、待处理事项、告警消息
- 查看 Agent 状态和任务状态
- 审批/驳回/确认关键节点
- 手动触发工作流
- 查看项目进度与最新产物摘要

验收标准：

- 小程序可完成审批和查看状态两个核心闭环
- 所有关键操作与 Web 端数据一致

### G. 项目过程证明书

- 为项目生成过程证明书
- 汇总 Agent 清单、任务时间线、关键产物、审批记录、测试摘要、交付摘要
- 生成可校验链接与摘要码

验收标准：

- 证明书可导出 PDF 和结构化 JSON
- 客户可通过验证页查看基础校验信息

## 6.2 P1 模块

- 客户可见的项目进度展示页
- 更细粒度的通知策略
- 模板版本管理
- Agent 成本统计面板
- 飞书/企微提醒接入

## 6.3 明确延后

- 通用型聊天面板
- 大型可视化低代码流程画布
- 完整多组织财务计费
- 深度企业权限矩阵
- 大规模第三方生态适配

## 7. MVP 内置模板场景

## 7.1 小程序项目交付流程

1. 需求整理 Agent 生成需求摘要
2. 前端 Agent 输出页面结构与组件清单
3. 编码 Agent 实现模块
4. 测试 Agent 执行回归
5. 文档 Agent 整理交付说明
6. 人工审批
7. 生成项目过程证明书

## 7.2 每周运营分析流程

1. 数据 Agent 拉取数据
2. 分析 Agent 生成洞察
3. 内容 Agent 生成周报
4. 人工确认
5. 自动发送客户周报

## 7.3 外包项目阶段汇报流程

1. 拉取本周任务与产物
2. 汇总 Agent 贡献
3. 生成阶段汇报
4. 人工审批
5. 发送客户并归档

## 8. 信息架构

## 8.1 Web 控制台

- 工作区首页
- 项目列表页
- 项目工作台
- 任务看板/列表
- 任务详情页
- Agent 列表与详情页
- 工作流模板页
- Run 详情页
- 审批中心
- 证明书中心
- 系统设置与接入配置

## 8.2 小程序端

- 首页概览
- 待处理审批
- 项目列表
- 项目详情
- Run 状态详情
- Agent 状态列表
- 告警与通知

## 9. 关键用户故事

## 9.1 项目负责人

- 作为项目负责人，我希望快速创建项目并绑定常用 Agent，以便立即启动标准交付流程。
- 作为项目负责人，我希望在一个看板中知道任务、Run 和审批卡在哪一步，以便及时干预。
- 作为项目负责人，我希望一键生成过程证明书，以便给客户做阶段验收。

## 9.2 审批人

- 作为审批人，我希望在小程序里查看待审批事项和上下文摘要，以便快速做出是否放行的决策。
- 作为审批人，我希望能看到驳回原因和历史审批记录，以便避免重复沟通。

## 9.3 客户交付人员

- 作为交付人员，我希望导出带验证链接的证明书，以便提升客户对过程透明度的信任。

## 10. 非功能需求

- 性能：项目工作台常规查询 P95 小于 800ms
- 一致性：关键状态变更必须具备审计记录
- 安全：所有关键操作需鉴权，敏感数据需脱敏存储
- 可观测性：Task、Run、Artifact、Approval 必须共享 Trace ID
- 可用性：MVP 阶段核心控制面月可用性目标不低于 99.5%

## 11. 数据指标埋点

- 项目创建数
- 活跃 Agent 数
- 工作流触发数
- Run 成功率
- 审批通过率和平均耗时
- 证明书生成数
- 模板复用率

## 12. MVP 验收门槛

- 至少 3 个典型流程模板可运行
- 可接入至少 2 类 Agent 执行器
- Web 端可管理项目、任务、Agent、Run、证明书
- 小程序端可完成审批、查看状态和异常提醒
- 可生成客户可读、可校验的过程证明书
