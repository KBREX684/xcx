# 风险、安全与运维基线

## 1. 目标

为 MVP 阶段建立最小可行但完整的风险控制、安全基线、监控和应急处理规范，确保系统在真实试点场景下具备基本稳定性与可信度。

## 2. 风险清单

| 风险 | 概率 | 影响 | 应对策略 |
| --- | --- | --- | --- |
| 用户认为现有工具拼装即可替代 | 中 | 高 | 聚焦移动调度、统一任务模型、过程证明三项独特价值 |
| 接入生态过于碎片化 | 高 | 高 | MVP 先支持少量高频接入，以 OpenAPI 为主，MCP 为补 |
| 产品范围膨胀 | 高 | 高 | 需求评审必须对照 MVP 边界，新增功能必须回答是否增强交付闭环 |
| 过程证明可信度不足 | 中 | 高 | 所有关键记录留痕、签名、摘要校验、验证页可查 |
| 小程序投入过大拖慢主线 | 中 | 中 | 小程序只保留审批、提醒、状态查看和轻量触发 |
| 外部执行器稳定性差 | 高 | 中 | 建立健康检查、超时、重试、隔离和人工接管机制 |
| 关键日志或产物丢失 | 低 | 高 | 对象存储归档、数据库审计、备份策略、重要产物摘要校验 |

## 3. 安全基线

## 3.1 身份鉴权

- Web / 小程序统一 JWT 鉴权
- 外部执行器使用独立 API Key
- 高风险接口支持时间戳签名校验

## 3.2 权限控制

- 工作区级资源隔离
- 项目级成员访问控制
- 审批操作只允许具备审批角色的成员执行
- 证书撤销、密钥轮换等高风险操作需二次确认

## 3.3 密钥与凭证

- API Key 加密存储
- 签名私钥不得硬编码入仓库
- 使用环境变量或密钥管理服务
- 密钥轮换需有版本管理和回滚预案

## 3.4 数据保护

- 敏感配置脱敏展示
- 原始 Prompt、外部凭证、内部回调 token 不对客户展示
- 日志和导出内容避免包含敏感头信息

## 3.5 审计要求

以下动作必须写入不可篡改审计事件：

- 登录与登出
- Agent 启用/禁用
- 模板发布
- Run 重试/取消
- 审批通过/驳回
- 证明书生成/撤销

## 4. 运维基线

## 4.1 监控指标

- API 请求量、错误率、P95 延迟
- Run 成功率、失败率、重试率
- 审批平均耗时
- 证明书生成时长和失败数
- 队列积压长度
- 外部 Agent 健康状态

## 4.2 日志规范

- 结构化日志
- 统一 `trace_id`
- 严禁打印明文凭证
- 错误日志必须带业务上下文和错误码

## 4.3 链路追踪

- 用户操作到 Run 执行再到证明书生成必须可串联
- 每个外部回调写入 Trace Span
- 审批动作作为关键业务事件单独埋点

## 5. 告警策略

P0 告警：

- API 全站不可用
- Run 大面积失败
- 证明书生成服务不可用
- 对象存储不可写

P1 告警：

- 某一类 Agent 长时间异常
- 队列积压超过阈值
- 小程序审批接口错误率升高

## 6. 备份与恢复

- PostgreSQL 每日全量备份
- 对象存储关键桶启用版本或定期备份
- 签名密钥独立备份并严格控制访问
- 每月至少演练一次恢复流程

## 7. 事故响应

| 等级 | 说明 | 响应目标 |
| --- | --- | --- |
| Sev-1 | 核心闭环不可用或严重数据风险 | 30 分钟内响应 |
| Sev-2 | 核心功能降级但可绕行 | 2 小时内响应 |
| Sev-3 | 次要功能异常 | 1 个工作日内处理 |

事故处理步骤：

1. 识别影响范围
2. 触发告警与责任人响应
3. 保护数据与停止扩散
4. 回滚或降级
5. 复盘并补齐监控或流程

## 8. 合规与对外声明边界

- MVP 阶段只宣称“过程可追溯、结果可校验”，不宣称法律认证能力
- 涉及客户数据时，需要明确数据保留策略和删除策略
- 如提供公开验证页，必须确保仅暴露必要元数据

## 9. 上线前必查项

- 关键接口开启鉴权
- API Key 与签名密钥来自安全配置
- 审计日志可查
- 备份任务已验证
- 关键告警已验证
- 回滚方案已演练

## 10. 运营观察重点

试点阶段重点观察：

- 哪类模板最常被复用
- 用户是否真的使用小程序审批
- 客户是否在意证明书中的哪些内容
- 外部执行器最常见失败原因是什么
- 平均一个项目需要多少次人工接管
