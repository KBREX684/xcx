# 测试与质量保障计划

## 1. 目标

建立一套适合 MVP 阶段的轻量但有效的质量体系，确保 `Agent 指挥台` 在快速开发的同时，不牺牲核心交付链路的稳定性、可信度和可追溯性。

## 2. 质量目标

- 核心闭环 `Project -> Task -> Run -> Approval -> Certificate` 必须稳定可测
- 关键状态流转必须正确、可回放、可审计
- 外部执行器失败、回调异常、审批驳回等场景必须有明确处理结果
- Web 与小程序在关键业务数据上保持一致

## 3. 测试分层策略

## 3.1 单元测试

覆盖重点：

- 状态机流转
- DTO 校验与领域规则
- 证明书摘要与签名逻辑
- 权限判断
- 错误码与异常转换

目标：

- 核心域服务覆盖率优先达到 80% 以上

## 3.2 集成测试

覆盖重点：

- API 与数据库读写一致性
- Run 创建与回调处理
- Artifact 入库与摘要计算
- Approval 与 Task/Run 状态联动
- Certificate 生成链路

## 3.3 契约测试

覆盖重点：

- OpenAPI Adapter 请求与回调格式
- Webhook 触发格式
- 小程序与 BFF 接口约定
- MCP Relay 抽象接口行为

## 3.4 端到端测试

覆盖重点：

- 创建项目并绑定模板
- 触发流程并查看任务与 Run 状态
- 小程序完成审批
- 生成并验证证明书

## 4. 测试环境规划

| 环境 | 用途 |
| --- | --- |
| Local | 开发联调、本地自动化测试 |
| Dev | 日常集成、前后端协作 |

| Prod | 正式使用环境 |

## 6. 核心验收用例

## 6.1 正常闭环

1. 创建项目
2. 绑定模板与 Agent
3. 触发工作流
4. Run 成功回调
5. 审批通过
6. 生成证明书
7. 验证页校验通过

## 6.2 异常场景

- Agent 回调超时
- 回调重复提交
- 审批驳回后重新执行
- 证明书重新生成并替换为新版本
- 小程序登录态失效后重新鉴权

## 6.3 边界场景

- 项目存在多个并发 Run
- 一个 Task 关联多个 Run 重试记录
- Artifact 缺失摘要时拒绝纳入证明书
- 已撤销证明书在验证页明确显示失效

## 7. 非功能测试

## 7.1 性能

- 项目工作台查询 P95 < 800ms
- Run 列表查询 P95 < 1000ms
- 证明书生成在普通项目规模下 < 30s

## 7.2 安全

- 越权访问测试
- API Key 泄露与失效测试
- 敏感字段脱敏检查
- Webhook 签名验证测试

## 7.3 稳定性

- Worker 重启后待处理 Run 恢复
- Redis 短时不可用时任务保护策略
- 外部执行器失败后的退避重试

## 8. 质量门禁

## 8.1 合并门禁

- Lint 通过
- 类型检查通过
- 单元测试通过
- 关键模块代码评审完成

## 8.2 预发布门禁

- 核心端到端用例通过
- 小程序审批主路径回归通过
- 证明书生成与验证检查通过
- 高优先级缺陷已关闭或有明确豁免

## 8.3 上线门禁

- 关键监控和告警已启用
- 回滚方案已确认
- 数据备份可用

## 9. 缺陷分级

- P0：无法完成核心交付闭环、数据错误、严重安全问题
- P1：关键功能可用但结果不稳定，影响内测
- P2：影响体验或次要流程
- P3：文案、样式、低影响问题

## 10. 质量责任分工

- 开发：单元测试、集成测试、自测清单
- QA：用例设计、回归验证、发布验收
- 产品：验收标准确认、试点反馈整理
- 架构/主工程师：关键路径质量兜底、非功能目标把关

## 11. 发布回归清单

- 项目创建与编辑正常
- 看板状态流转正常
- 模板触发正常
- OpenAPI 执行器调用和回调正常
- 审批动作生效且可追溯
- 小程序待审批列表正常
- 证明书可生成、可下载、可验证
